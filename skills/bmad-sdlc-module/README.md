# BMAD SDLC Conductor

One skill for the whole BMAD software development lifecycle. Instead of choosing among `bmad-prd`, `bmad-architecture`, `bmad-create-epics-and-stories`, `bmad-build`, `bmad-testarch-*`, and `bmad-retrospective`, invoke `bmad-sdlc` and follow the menu.

It:

- detects whether the project uses the v6 flow (epics + `sprint-status.yaml`) or the current flow (Sofia + `tickets.toml`);
- keeps a durable, committed plan at `_bmad-output/sdlc/plan.yaml` with an append-only `.memlog.md`;
- presents a two-level menu: phase, then action, with the owning role and gate;
- hands each phase to the right skill in a fresh context, then validates the artifact;
- asks at every gate and records every decision and override;
- covers greenfield, feature, fix, and audit tracks.

## Install

Put the package where the target project can read it, then load `setup/SKILL.md`. It is the only step list: copy the skill, place `module-help.csv`, run the detector, and optionally initialize the ledger. Invoke `bmad-sdlc` when it finishes.

The setup skill never edits `_bmad/_config/`; the BMAD installer owns those files. To make the help entry appear in `bmad-help`, re-run the installer so it assembles `_bmad/bmad-sdlc/module-help.csv` into the catalog.

## Layout

```
bmad-sdlc-module/
  module.yaml              # module metadata
  module-help.csv          # help catalog entry
  setup/SKILL.md           # bmad-sdlc-setup
  scripts/package.sh       # rebuild skills/bmad-sdlc from the canonical source
  skills/bmad-sdlc/        # generated distributable copy
    SKILL.md
    customize.toml
    assets/plan-template.yaml
    references/*.md
    scripts/sdlc_plan.py
    scripts/tests/test_sdlc_plan.py
```

**Canonical source:** `{repo}/.agents/skills/bmad-sdlc/`. The copy under `skills/bmad-sdlc/` is generated by `scripts/package.sh`; do not edit it by hand. The package excludes authoring-only `evals/`; run `scripts/package.sh --check` to detect drift between the canonical tree and the distributable copy.

## Requirements

- Python 3.11+ and `uv` (the ledger helper uses `ruamel.yaml` via a PEP 723 header).
- A BMAD install for the actual delivery work. The conductor can plan without it, but actions are blocked until the target skills exist.
- A harness that can load skills and, ideally, spawn subagents. Without subagents, the conductor falls back to inline or user-run handoffs.

## Compatibility

- **v6.12.x** — `bmad-help`, `bmad-create-epics-and-stories`, `bmad-sprint-planning`, `sprint-status.yaml`.
- **current docs model** — `bmad` hub, `bmad-agent-po` (Sofia), `tickets.toml`, `bmad-tea`.
- Detection is automatic; a missing skill is reported and the action is blocked rather than silently substituted.

## State

- `{workflow.ledger_path}` (default `_bmad-output/sdlc/plan.yaml`) — the SDLC overlay (position, gate levels, per-ticket gates, decisions, pointers). Commit it.
- `{workflow.memlog_path}` (default `_bmad-output/sdlc/.memlog.md`) — append-only audit trail. Commit it.
- BMAD artifacts remain the source of truth for ticket/story status; the ledger never overrides them.
