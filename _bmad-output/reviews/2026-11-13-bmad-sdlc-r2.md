## Findings

### Adversarial (3)

- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:109,550-589,3040-3060`** — `done` closes a non-audit workstream that has passed per-ticket gates and no build evidence at all. `GATE_NAMES["build"] = ()`, so the phase-gate evidence loop never examines the build phase; `artifact_ticket_ids` returns `None` when no `tickets.toml` or `sprint-status.yaml` is readable, so the overlay check is skipped. Repro: `init --track fix --size trivial`, `ticket --id 1 --gate ticket|review|done --status passed`, then `done` → `ok: true, status: done` with only `plan.yaml` and `.memlog.md` on disk. Fix: when `tickets` is non-empty and no ticket artifact is readable, require `--accept-missing-tickets --reason` (or refuse), and give the build phase an evidence requirement. If unaddressed: the “a passed gate without evidence is not a pass” contract (gate-matrix §Phase completion, ledger-schema §Script operations) is false for the build phase.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2513-2525,2810-2905`** — `ticket --status passed` bypasses the blocked→passed guard that `set` enforces. Repro: `set --path tickets.1.gates.review.status --value blocked`, then `set … --value passed` fails with “a blocked gate cannot be passed”, but `ticket --id 1 --gate review --status passed` succeeds and `validate` stays clean. Fix: run `_guard_blocked_gate` and `_guard_decided_metadata` in `cmd_ticket`, or route both commands through one gate-write function. If unaddressed: a gate blocked on missing evidence is recorded as passed and the blocker disappears.
- **`.agents/skills/bmad-sdlc/SKILL.md:106`** — The projection sentence says the headless block “omits the open lists and ticket detail”, but the block includes `open_gates` and `blocked_gates`; the omitted fields are the per-level counts `required_open`, `conditional_open`, `optional_open`. Fix: “it omits the per-level open counts and ticket detail.” If unaddressed: a reader adds or removes the wrong keys when reconciling the block with `summary`.

### Edge-Case Hunter (2)

- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2810-2905`** — `ticket --status open` on a decided gate silently clears `decided_at` and `override_reason` and can write an out-of-order ledger. Repro: pass `ticket` and `review` on ticket `1`, then `ticket --gate ticket --status open`; the command returns ok and `validate` then fails with “review is decided before build.ticket is passed.” A reasoned override reopened the same way loses its reason. Fix: refuse `open` on a decided ticket gate without an explicit reopen reason, and re-check the order guards on reopen. If unaddressed: a command that reports success leaves a ledger `validate` rejects, and an audit reason is erased.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:1075-1090,2278-2330`** — `set --path tickets.<dotted-id>.gates.<gate>.status …` is accepted, but `get_parent` splits the id at the dots and creates a phantom nested ticket (`tickets."1"."3"`). Repro: `ticket --id 1.3 …` then `set --path tickets.1.3.gates.review.status --value passed` → ok, then `validate` fails with “tickets.1.gates must be a mapping”. Fix: reject a ticket-id segment containing `.` in `set` and point at the `ticket` command. If unaddressed: the ticket ids the docs say to use with `ticket` corrupt the ledger through `set`.

### Verification Gap (4)

- **`.agents/skills/bmad-sdlc/scripts/tests/test_sdlc_plan.py:1658-1699`** — No test covers the three write-path gaps above. The `test_done_refuses_missing_evidence_and_a_blocked_phase` case passes because it sets a stale *optional* `artifacts.spec` pointer, not because ticket gates require evidence; remove that pointer and its `done` would succeed. Fix: add a terminal-evidence test (tickets passed, no artifacts, `done` refuses unless accepted) and tests for `ticket` blocked→passed, `ticket --status open` on a decided gate, and dotted-id `set`. If unaddressed: all three regressions pass the suite.
- **`.agents/skills/bmad-sdlc/evals/cases.json:133-146`** — `feature-one-session` asserts “status is blocked because bmad-build is missing”, but the immediate blocker is `bmad-spec` (`frame.spec`); the assertion passes only because both are absent. Fix: assert the reason names the missing skill of the action, or accept either. If unaddressed: a run that blocks for the wrong reason still scores.
- **`.agents/skills/bmad-sdlc/evals/cases.json:35-48`** — `fix-trivial` asserts `open_gates … do not require … verify.trace`, yet `open_gates` literally contains `verify.trace` (optional). Fix: say “no open gate is required” explicitly. If unaddressed: correct and incorrect outputs can both pass or fail for the wrong reason.
- **`.agents/skills/bmad-sdlc/evals/cases.json:28-32`; `evals/README.md:67-75`** — `continue-with-ledger` passes by reporting the dangling `docs/bmad-sdlc.md` pointer (the case stages only the ledger and memlog), not by resuming at an open required gate. The installed-BMAD ready path and the write loop remain unverified (deferred V8/V9). Fix: a harness that can stage a directory/target path. If unaddressed: resume-at-open-gate and `status: ready` can regress without an eval failing.

### Editorial Structure / Prose (1)

- **`.agents/skills/bmad-sdlc/references/ledger-schema.md:266`** — Lists `phases` as a whole map replaceable with `--replace --reason`, but `_validate_path` rejects a bare `phases` path with “unknown phase in path: phases”. Fix: drop `phases` from the list or allow the whole-map write. If unaddressed: a documented command fails.
