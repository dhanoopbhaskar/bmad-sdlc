# Review: bmad-sdlc

**Content:** commit `e0388e8` (parent `e82c98a`) — the new `bmad-sdlc` conductor skill, its ledger helper, tests, evals, references, distributable module, design docs, and committed runtime ledger.

**Class:** mixed — Markdown skill/documentation plus Python CLI code. **Lenses run:** adversarial, edge-case-hunter, verification-gap, editorial structure, editorial prose.

**Scope note:** the generated mirror `skills/bmad-sdlc-module/skills/bmad-sdlc/**` is byte-identical to the canonical tree and was excluded from the review. Other vendor `bmad-*` skills were not reviewed.

**Verification performed for this review:** the 70-test ledger suite (`uv run --no-cache python -m unittest discover ...`) passed in 460 s; the 10 quality eval cases were run (`run_evals.py --mode quality --workers 3`) and every transcript was graded against its rubric with the stock grader contract. Trigger mode was not run: `evals/README.md` documents that the stock parser cannot read opencode load events.

**60/62 expectations passed; 8/10 cases fully passed.** The two failures are the same contract mismatch, not two unrelated defects.

The graded runs also exposed six things the rubrics did not assert directly:

- `blocked_gates` was `[]` in several blocked runs while the build phase was blocked; `status: blocked` came from phase state, not a named gate.
- For the audit case, `next_action.gate` was `build.review` while `open_gates` named `build.audit.review` — one gate, two names.
- `next_action.skill` was `null` in one run while the ledger cached `bmad-spec`; the emitted block and the ledger disagreed.
- Two runs wrote scratch JSON to `/tmp` while the input said to work only in the project root; another run's first `init` failed on template resolution and silently retried.
- `detect` reported `skills: ['bmad-sdlc']` with evidence `BMAD skills exist but the model-specific skills do not match` — the conductor counts itself as a BMAD install (see the adversarial and verification-gap findings).
- Because the documented eval command passes `--mode` twice, the bare baseline was never produced by that command; the numbers above are quality-mode grades, not a skill-vs-bare comparison.
