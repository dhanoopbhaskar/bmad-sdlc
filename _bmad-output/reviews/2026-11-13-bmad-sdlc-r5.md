# Review: bmad-sdlc (round 5, current tree)

**Content:** the new `bmad-sdlc` conductor skill in its current working tree — `SKILL.md`, the six references, `customize.toml`, `scripts/sdlc_plan.py`, `scripts/tests/test_sdlc_plan.py`, `evals/`, the ledger template, the distributable module, and the docs that describe it (`docs/bmad-sdlc.md`, `README.md`, `AGENTS.md`).

**Class:** mixed — code plus documents. **Lenses run:** adversarial, edge-case-hunter, verification-gap, editorial structure, editorial prose (prose on top of structure).

**Context:** this is a fifth pass. Rounds 1–4 found and fixed 178 issues. This pass does not re-report those; it reviews the current tree, the guard code the fixes introduced, and the verification story. The two deferred eval-harness limits (V8/V9 in round 1) are still documented in `evals/README.md` and are not re-reported here.

**Findings: 67** — 18 adversarial, 8 edge-case, 13 verification-gap, 18 editorial structure (16 changes and 2 deliberate preserves), 10 editorial prose.

Three findings change persisted state or the audit contract and are worth fixing before anything else:

1. `done` lets one arbitrary file in `phases.<phase>.evidence` stand in for every artifact check in that phase — including the two-file `plan.ux` rule (`sdlc_plan.py:3477`).
2. `verify-return --allow-empty-artifacts` accepts a `done` return with zero artifacts and zero evidence, which `handoff-protocol.md:100` says it must not.
3. `--memlog` expands `{project-root}` against the shell's working directory, not `--project-root`, so the audit trail can be written outside the project.

## Adversarial (18)

- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3463-3488`** — `if not keys or phase_evidence: continue` runs before the `plan.ux` branch, so any single readable file appended to `phases.<phase>.evidence` satisfies every required/conditional gate in that phase and skips the DESIGN+EXPERIENCE check entirely. **Fix:** move the UX pair check and the artifact-key check ahead of the early return, and require a claimed evidence path to correspond to the gate's `ARTIFACT_GATES` key. **Consequence:** a project closes with planning gates "evidenced" by an unrelated file, and the audit trail records a clean close.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:4094-4097`** — `--allow-empty-artifacts` also waives an explicitly empty `evidence` list. **Fix:** split the conditions; the evidence check stays unconditional. **Consequence:** reproduced — `--return '{"status":"done","artifacts":[],"evidence":[],"open_questions":[]}' --allow-empty-artifacts` returns `ok: true`, contradicting `handoff-protocol.md:100` ("it does not waive missing evidence").
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:497-500`** — `resolve_memlog` expands the token against `Path.cwd()` even when `--project-root` is supplied. **Fix:** expand against the command's project root exactly as `_plan_path` does. **Consequence:** `done`/`reconcile`/`verify-return` invoked from a parent directory create a second audit trail outside the project; the only test runs with `cwd` equal to the project root, so it cannot see the split.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:1993-2000`** — `validate` emits `{"ok": false}` and exits 0; `reconcile` and `verify-return` share the pattern (`emit` defaults to code 0). **Fix:** exit 1 when `ok` is false, and document one exit-code contract in `ledger-schema.md` §Script operations. **Consequence:** a preflight `validate && continue`, a CI step, or an agent checking `$?` proceeds on a corrupt ledger.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:239-256,4086-4090`** — every write leaves `<ledger>.lock` and `.memlog.md.lock` behind, and `ledger_touched` is a substring test over `git status`. **Fix:** unlink the lock file on release, match whole paths, and have `setup/SKILL.md` add `*.lock` to the target `.gitignore`. **Consequence:** in a fresh install the returned `ledger_touched` is always true, so the one hard signal for "a subagent edited the ledger" stops flagging real edits.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2986-2992`** — `set --path phases.<phase>.evidence --replace` bypasses the append-only guard because the guard is `and not args.replace`. **Fix:** reject replace/null for the evidence path. **Consequence:** recorded gate evidence is silently discarded; the audit line says only "replaced".
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3556-3578`** — the close event never names overridden gates, though `gate-matrix.md:51` requires an override to be visible in the close summary. **Fix:** collect both phase-level and per-ticket overrides and append them to `close_notes`. **Consequence:** an overridden required gate closes indistinguishably from a clean close.
- **`.agents/skills/bmad-sdlc/references/menu.md:7-20`** — the dashboard renders the flat `required_open`/`conditional_open`/`optional_open` lists on every phase row. Those lists are global and include per-ticket gates, so each row shows the same totals. **Fix:** use `phases[].required_open`/`…` for the rows and keep the flat lists for the totals line. **Consequence:** the dashboard misstates where the work is, which is the first thing activation renders.
- **`.agents/skills/bmad-sdlc/SKILL.md:30-31`** — the headless block is said to "project `summary`", but an active `summary` nests `track`/`size`/`status` under `workstream`; only `model` and `phase` are top-level. **Fix:** state the mapping or flatten the three fields in the payload. **Consequence:** two agents following the same sentence emit different JSON shapes, and the eval rubrics assert a projection the script never supplies.
- **`.agents/skills/bmad-sdlc/evals/adapter.json:16` with `bmad-eval-runner/scripts/run_evals.py:187-201`** — the runner symlinks the whole skill into the case root, so `evals/cases.json` (all ten rubrics) is readable inside the project root, while `SKILL.md:120` names only `case.json`, `prompt.txt`, and "a rubric". **Fix:** add `evals/` to the never-read list and stage the skill without it. **Consequence:** a run can self-grade from inside the project root while obeying the literal guardrail.
- **`.agents/skills/bmad-sdlc/references/version-adapters.md:56` vs `SKILL.md:87`** — one document says to record a missing core skill in the phase note; the other says only to set the report status and keep the action. **Fix:** pick one and document the exact command. **Consequence:** a fresh agent either loses the reason from the ledger or discovers an undocumented write path and hits a refusal on a paused workstream.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:707-709`** — `detect` treats any `bmad-tea-*` directory as `test_style: bmad-tea`, while `version-adapters.md:56` calls those names a missing-skill error. **Fix:** match only `bmad-tea`. **Consequence:** a `ready`-looking detection result points the conductor at a name the resolver refuses to use.
- **`.agents/skills/bmad-sdlc/references/phase-map.md:39` vs `scripts/sdlc_plan.py:794-808`** — phase-map says `trivial` skips verification gates, but the audit branch returns before any size handling, so `audit` + `trivial` still requires `verify.trace`. **Fix:** state the audit exception in phase-map or gate the level on size. **Consequence:** the cheapest track/size combination is scheduled as a full verification pass.
- **`skills/bmad-sdlc-module/setup/SKILL.md:22-26`** — the install step runs `rm -rf "{project-root}/<skills-dir>/bmad-sdlc"` with two LLM-substituted placeholders and only prose as a guard. **Fix:** resolve the path, assert its basename and prefix, then `mv` to a timestamped backup and delete only after the copy succeeds. **Consequence:** a blank or duplicated substitution turns "copy the skill" into an unbounded recursive delete, in a product whose own guardrail is consent before irreversible actions.
- **`skills/bmad-sdlc-module/setup/SKILL.md:48`** — points at "a `customize.toml` override" in the target project; overrides live in `_bmad/custom/bmad-sdlc.toml`. **Fix:** name the real override file and tell the agent to run the resolver. **Consequence:** the agent hunts a nonexistent file, then `init` writes the default ledger while the workflow expects another path.
- **`skills/bmad-sdlc-module/module.yaml:3` vs `package.sh:31-45`** — `version: 0.2.0` is the only marker and it is not copied into the skill, so an installed conductor carries no identifier and update is a silent `cp -R`. **Fix:** ship a version file inside the skill and compare it during setup. **Consequence:** no way to answer "is this install current?" from the target project.
- **`docs/bmad-sdlc.md:155`** — says detection is limited to `.agents/skills` "or the project manifest", while `SKILL_DIRS` scans six roots (`.agents`, `.claude`, `.cline`, `.bob`, `.agent`, `.adal`). **Fix:** point at the single list in the script. **Consequence:** an audit clears a `.claude/skills` install the design says cannot be seen.
- **`.agents/skills/bmad-sdlc/references/menu.md:102`** — "A `phase.unblock` next action" is written as a literal id; the metavariable is `<phase>.unblock` everywhere else. **Fix:** use the bracketed form. **Consequence:** an agent looks for a phase named `phase`, or reads the row as an action id rather than a template.

## Edge-case hunter (8)

- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:497-510`** — `--memlog` can resolve to the ledger itself (copy-paste of `{workflow.ledger_path}`, or a hand-edited `bmad.memlog`); `append_memlog` then re-locks `plan.yaml.lock` while `plan_locked` holds it. **Fix:** refuse a memlog path equal to the ledger. **Consequence:** reproduced — every write hangs with no JSON and no error (killed at 8 s).
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:1477-1481`** — `init --project-root /proj --plan _bmad-output/sdlc/plan.yaml` resolves the relative `--plan` against the shell's cwd, not `/proj`, because `expand_project_root` only substitutes the token. **Fix:** join a relative `--plan` to the resolved project root before `.resolve()`. **Consequence:** the ledger and audit trail land in the wrong directory, and later commands infer the wrong root for evidence.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:1685-1697,3077-3080`** — `set --path active_workstream --null` is accepted while a workstream is still `active`, and `validate` has no "active workstream must be named" rule. **Fix:** refuse the null while any workstream is active. **Consequence:** reproduced — `validate` is clean, `summary` loses its active target, and scoped writes fail with no explanation.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2452-2475`** — `set --path phases.<phase> --replace --value '{"note":"half"}'` returns `ok: true`; `validate` then rejects the ledger for a missing `status`, `gate`, and `evidence`. **Fix:** require the required fields (or defaults) before writing a phase replacement. **Consequence:** reproduced — the tool reports success for a ledger it later refuses, the exact "no silent success" guardrail.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:4117-4123`** — `--accept-questions` logs "accepted open questions" before the verdict is computed, so a return rejected for a missing artifact still records the questions as accepted. **Fix:** log only after `ok` is true. **Consequence:** the audit trail claims a decision the conductor did not make.
- **`.agents/skills/bmad-sdlc/SKILL.md:29` with `sdlc_plan.py:1422-1428`** — the terminal recommendation `close.mark_done` carries `skill: null`, but the headless rule says a missing `next_action.skill` means `blocked`. **Fix:** exempt `close.mark_done` (and `<phase>.unblock`) from that rule. **Consequence:** the normal close gate is reported blocked with an install step for a skill that never existed.
- **`.agents/skills/bmad-sdlc/references/handoff-protocol.md:50-51`** — the brief template keeps the skill's own `{}` tokens beside the `<>` slots the conductor fills. **Fix:** use `<resolved ledger path>` / `<resolved audit path>`. **Consequence:** the subagent receives a token it cannot resolve and may edit the ledger.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2898`** — ticket ids are normalized with `{str(key): key}`, so a legacy ledger holding both `1:` and `"1":` silently keeps the last one. **Fix:** make `validate` reject duplicate ids after normalization, or normalize on load. **Consequence:** two records collapse to one id; guards read one, summary counts one, `validate` stays clean.

- **`scripts/sdlc_plan.py:3432-3438,3838-3844`** — `done`/`reconcile` refuse an artifact pointer outside the project root, but only `verify-return` has an outside-root test. **Fix:** stage an outside pointer and assert both commands refuse it. **Consequence:** the scope guardrail can regress unnoticed.

- **`scripts/sdlc_plan.py:422-435`** — `detect`'s `_bmad/_config/skill-manifest.csv` branch is untested; every detection fixture stages a skills directory that already supplies the same names. **Fix:** a project with only the manifest must still detect the model. **Consequence:** installer-installed projects can fall to `unknown` with no failing test.
- **`scripts/sdlc_plan.py:116-123`** — only `.agents/skills` is exercised; the other five roots in `SKILL_DIRS` (including the `.claude/skills` layout `setup/SKILL.md` recommends) have no test, and `skills_dir` is never asserted. **Fix:** one test per documented install layout. **Consequence:** a mistyped root makes every Claude Code/Cline install detect `unknown`.

- **`scripts/sdlc_plan.py:700-712`** — `test_style` and both `hub` branches are asserted nowhere, though `README.md:174` advertises them. **Fix:** a fixture with `bmad-tea` and one with `bmad` should pin both. **Consequence:** the detector can send the conductor to the wrong test skill while the README still claims correct detection.
- **`scripts/sdlc_plan.py:2244,2253`** — `test_summary_after_done_keeps_full_shape` pins ten keys but not `optional_open` or `workstreams_detail`; `menu.md:7,26` depends on both. **Fix:** assert both, including the per-workstream brief keys. **Consequence:** the menu can render an incomplete dashboard with the "full shape" test green.
- **`scripts/sdlc_plan.py:449-457`** — the fourth config layer, `_bmad/custom/config.user.toml`, is never written by the precedence test (only `config.toml`, `config.user.toml`, and `custom/config.toml`). **Fix:** add the personal custom layer and assert it wins. **Consequence:** a personal override can stop applying after a refactor, silently changing every artifact path.
- **`scripts/sdlc_plan.py:1505,4285`** — `--default-track` is implemented and documented as a customization knob, but neither the docs' `init` invocations nor any test passes it. **Fix:** test `init --default-track fix` end to end. **Consequence:** the knob is dead in practice, and the fallback silently stays `feature`.

## Notes

- Rounds 1–4's fixes hold: the write loop, reopen ordering, dotted ids, ticket guards, and module packaging all behaved as documented in the reproductions. The findings above are new seams, not regressions of those fixes.
- The unit suite is the only place the write loop is verified end to end. Eleven of the thirteen verification-gap findings are tests that would stay green if the behavior they name were deleted.
- The eval harness cannot currently self-contain a case: the skill symlink escapes the case root, and the rubric metadata is readable inside it. That is a `bmad-eval-runner` capability limit, not something to fix by editing the vendor runner.
