## Adversarial

**A1** `scripts/sdlc_plan.py:331-334,393-397` — The parent directory is created before any path validation.
- **Trigger:** any command given a `--plan` whose parent does not exist (`set --plan /tmp/x/plan.yaml`, `init --plan …`). `plan_locked` takes `file_lock` before the command runs, and `file_lock` calls `lock_path.parent.mkdir(parents=True, exist_ok=True)`.
- **Guard:** validate the plan path (containment, existing parent) before locking, and never create the parent inside `file_lock`.
- **Consequence:** a typo or hostile `--plan` creates directories and a `plan.yaml.lock` outside `{project-root}` even though the command fails, violating §Isolation. *Reproduced*: a failing `set --plan <scratch>/outofroot/deep/plan.yaml` left `outofroot/deep/plan.yaml.lock` behind.

**A2** `scripts/sdlc_plan.py:660-671` — An absolute `--memlog` escapes containment when no project root is known.
- **Trigger:** a ledger at a non-default path, no `--project-root`, and `set --memlog /absolute/path`. `_known_project_roots` is empty, so the `if roots and not _inside(...)` check is skipped.
- **Guard:** require `--project-root` for an explicit `--memlog` when no root can be derived, or derive the root from the ledger and enforce containment.
- **Consequence:** the audit trail is written outside the project, splitting it from the committed ledger. *Reproduced*: `set --plan plan/plan.yaml --memlog ../evil.md` returned `ok: true` and created `evil.md` beside the project.

**A3** `scripts/sdlc_plan.py:2956-2961,3777-3778` — A derived field accepts a write and reports the unpersisted value.
- **Trigger:** `set --path current_phase --value close`. `_validate_value` accepts the enum, the write succeeds, then `refresh_workstream` overwrites the field.
- **Guard:** reject `current_phase` and `next` in `_validate_path` as derived, or return the value that landed.
- **Consequence:** the command returns `ok: true` and `value: "close"` while the ledger still reads `plan`; the conductor believes it moved. *Reproduced*.

**A4** `scripts/sdlc_plan.py:2691-2780,77-90; validate 1967-2293` — A misspelled root is written as a new workstream key.
- **Trigger:** `set --path gats.plan.requirements.status --value passed` (or `append --path notev2`). No branch in `_validate_path` matches, so the value is created under the typo; `validate` never checks workstream keys even though `WORKSTREAM_ROOTS` exists.
- **Guard:** reject a scoped path whose root is neither a doc root nor a workstream root; add a `validate` error for unknown keys.
- **Consequence:** the intended gate never advances, a phantom subtree persists, and `validate` reports clean. *Reproduced*: `gats:` appears in the ledger and `validate` returns `errors: []`.

**A5** `scripts/sdlc_plan.py:1533-1548,3314; references/gate-matrix.md:74` — Phase completion ignores a blocked optional gate.
- **Trigger:** an optional gate set `blocked`, then the phase set `done`.
- **Guard:** make `phase_blocking` treat any blocked gate as blocking, or narrow gate-matrix.md §Phase completion to required/conditional.
- **Consequence:** the documented rule ("no gate in the phase is blocked") is false, and `summary` calls the phase complete with an unresolved blocked gate. Note the same file's `done` bullet already says "required or conditional", so gate-matrix contradicts itself as well as the code.

**A6** `scripts/sdlc_plan.py:3282-3285` — Moving a done phase to `blocked` is not treated as a reopen.
- **Trigger:** `set --path phases.close.status --value blocked` on a done phase; the guard only requires `--reason` for `active`/`pending`.
- **Guard:** require `--reason` for every transition out of `done`/`skipped`, including `blocked`.
- **Consequence:** a completed phase is silently regressed, the audit line records no rationale, and the workstream becomes unclosable.

**A7** `scripts/sdlc_plan.py:1551-1586; references/phase-map.md:86; references/ledger-schema.md:181` — `optional_actions` never carries conditional gates.
- **Trigger:** `optional_actions` skips every gate whose level is not `optional`, while phase-map.md says "Conditional gates are available early: `optional_actions` exposes them".
- **Guard:** include open conditional gates (tagged with their level) or correct phase-map.md to name the actual mechanism (`conditional_open` / the phase action menu).
- **Consequence:** the documented early path for UX, architecture, and test setup does not exist in the machine-readable list; a conductor following phase-map cannot offer the gate without inventing an action. *Reproduced*: a feature/one-session ledger returns `plan.sprint` and `plan.architecture` only (architecture resolves optional at that size); `plan.ux` is absent.

**A8** `scripts/sdlc_plan.py:5041-5052; references/handoff-protocol.md:109-111` — The integrity check is opt-in.
- **Trigger:** `verify-return` without `--expect-ledger-sha`/`--expect-memlog-sha` returns `ok: true` for a valid return; the docs suggest running it without the flags first.
- **Guard:** require both digests for acceptance, or emit a distinct `digest_check: "not_run"` and a reason so "no digests" cannot read as a pass.
- **Consequence:** a subagent that edited the ledger or audit trail during the handoff is accepted whenever the caller omits the flags.

**A9** `scripts/sdlc_plan.py:4796-4821; compare done 4220-4246` — `reconcile` misses gates that have no artifact key and no phase evidence.
- **Trigger:** a passed/overridden required or conditional gate with no `ARTIFACT_GATES` entry (`verify.nfr`, `verify.test_review`, `close.retro`, `close.walkthrough`) and no phase evidence. `done` appends "no artifact key and no phase evidence"; reconcile's `if keys and not any(...)` never flags it.
- **Guard:** give reconcile the same empty-`keys` branch as `done`.
- **Consequence:** the resume flow reports a clean ledger, then `done` refuses at the final gate, after the work is done.

**A10** `scripts/sdlc_plan.py:4757-4772; compare done 4260-4289 and cmd_ticket 3980-3992` — Ticket-gate evidence pointers are never reconciled.

- **Guard:** reject a nonexistent ticket-gate evidence pointer at write time, and resolve ticket-gate pointers in reconcile.
- **Consequence:** reconcile says clean while a passed ticket gate points at a missing file; `done` fails late in the build loop.

**A11** `scripts/sdlc_plan.py:4133-4145,2237-2249; references/gate-matrix.md:57` — Three paths disagree about an overridden review.
- **Trigger:** a hand-edited ledger with `done: overridden` and `review: overridden`. `_guard_ticket_order` requires a passed review, but `cmd_done` and `validate` accept an overridden one.
- **Guard:** require `review == "passed"` in `cmd_done` and `validate` whenever `done` is decided, matching the guard and gate-matrix.
- **Consequence:** a workstream closes on an overridden review, which gate-matrix calls non-negotiable ("an overridden review is not enough"). Which path enforces the rule depends on how the ledger was written.

**A12** `scripts/sdlc_plan.py:5291,5373-5374,8` — Two argument errors bypass the JSON contract.

- **Consequence:** the module promises JSON errors and every caller reads JSON; these routes return usage text instead. *Reproduced*.

**A13** `references/headless.md:24; SKILL.md:74; scripts/sdlc_plan.py:2557-2562; references/version-adapters.md:29` — `skill_manifest_only` never triggers the missing-skill rule.

## Edge-Case Hunter

**E1** `scripts/sdlc_plan.py:1607-1608,4110-4111` — `summary` recommends a close that `done` refuses.
- **Trigger:** non-audit build phase skipped with no ticket (e.g. fix/trivial, build skipped). `phase_blocking` sees no gates, so the phase is complete and `next_action` is `close.mark_done`; `done` requires a built ticket.
- **Guard:** treat a non-audit build phase with no tickets as blocking (emit `build.ticket`), matching `done`'s check.
- **Consequence:** the conductor recommends `close.mark_done`, the command fails with `build.ticket (no ticket built)`, and the only fix is reopening build. *Reproduced*.

**E2** `scripts/sdlc_plan.py:1533-1548` — A blocked optional gate does not block its phase.
- Overlaps **A5**. `phase_blocking` filters on level before status, so an optional `blocked` gate is invisible; the phase can be set `done`, and `summary.blocked_gates` omits it.

**E3** `scripts/sdlc_plan.py:3153-3183` — A decided gate can be blocked on a done phase, producing a ledger `validate` rejects.
- **Trigger:** all gates decided, phase set `done`, then one gate set `blocked --reason …`. The write is accepted; `validate` then errors "phases.plan is done with undecided gates".
- **Guard:** run the phase/build order guards for every status change out of a decided state, not only `open`, or reopen the phase atomically.
- **Consequence:** the tool writes a state it then refuses to validate. *Reproduced*.

**E4** `scripts/sdlc_plan.py:4762-4770` — `reconcile` ignores the containment of phase evidence.
- **Trigger:** phase evidence appended as an absolute path outside the project root. The loop computes `project_relative` (catching `ValueError`) but only checks `is_file()`.
- **Guard:** mark an outside-root pointer as missing evidence, and reject it in `cmd_append`.
- **Consequence:** reconcile exits 0 and `--write` never blocks; only `done` rejects it, at the end. Confirmed by reading the branch.

**E5** `scripts/sdlc_plan.py:3240-3265` — The documented unblock is refused while another phase is active.
- **Trigger:** a `<phase>.unblock` next action tells the conductor to `set phases.<phase>.status active`; `_guard_active_phase` refuses because the earlier phase is still `active`.
- **Guard:** exempt blocked→active, or state the precondition in menu.md:109.
- **Consequence:** the recommended legal move fails and the phase stays blocked with no documented recovery order.

**E6** `scripts/sdlc_plan.py:3205-3220,3616-3619` — `decided_at` accepts arbitrary JSON on a decided gate.
- **Trigger:** `set --path gates.<phase>.<gate>.decided_at --value <non-string>`. `_guard_decided_metadata` fires only for `None`; `_validate_value` does not type-check the field, and the node-replacement path preserves (or stamps) it only for whole-node writes.
- **Guard:** require an ISO string and refuse `decided_at` writes on a decided gate, as node replacement does.
- **Consequence:** backdated or non-string decision timestamps pass `validate` and reach `summary`. *Reproduced*: `decided_at: 12345` persisted and validated clean.
