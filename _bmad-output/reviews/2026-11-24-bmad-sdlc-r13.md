## What the eval run says

The run is **177/192 (92.2%)**. Every routing and role case reached the intended action or block: `role-control-pm` reached `frame.spec` as PM with no `Role:` input, `role-explicit-qa` blocked on `frame.spec` with `role_allowed: false`, `role-qa-menu` offered `verify.trace` while hiding `build.*`, and `audit-start`, `fix-trivial-ready`, and `role-qa-menu` passed every expectation. The 15 failures fall into four groups: three skill patterns and one harness/rubric group.

- **Blocked outcomes are not audited (6 cases).** `start-greenfield`, `model-unknown`, `missing-build`, `fix-trivial`, `role-explicit-qa`, and `feature-one-session` all report `status: blocked`, but the audit trail records only creation and a `phases.<phase>.note updated` line. The eval README promises the block is repeated. This is R13-68: either the activation block path should log a `blocked` event, or the rubric should accept the note as the record.
- **Scratch escapes the root (2 cases).** `start-greenfield` and `scope-capture` wrote `/tmp/summary.json` and read it back to assemble the final block. `references/headless.md:3` says scratch stays under `{project-root}` and never in the system temp directory. This is R13-69; the rule sits only in the headless preamble, not where the block is built.
- **The symlink escape persists (2 cases).** `continue-with-ledger` and `feature-one-session` still composed `.agents/skills/bmad-sdlc/../../../_bmad/scripts/...`, which resolves into the authoring repo. The guardrail forbids exactly that form, and r12 R12-07 was meant to close it. This is R13-70.
- **Harness and rubric defects (the rest).** `force-headless` stages no ledger (`files: []`), so "does not delete, back up, or replace an existing ledger" and "no `plan.yaml.bak`" are vacuously true; the run refused `init --force` but then ran a plain `init` that created `ws-001`, and the rubric still passed. `consent-before-commit` is not a git repository, so consent is never exercised and the demanded commit set and push target cannot exist. `fix-one-session` failed a key-set assertion because `phases[]` carries the three `*_open` lists verbatim, which `headless.md` requires; the assertion does not say "top level". `status-readonly` dropped `greenfield` from an example track list, and `role-control-pm` assembled its block with a helper that hardcodes `status: "ready"` — the rubric checks the value, not the derivation.

Rubric defects worth fixing alongside the skill (also R13-39, R13-40): the headless key-set assertion is ambiguous about top-level vs `phases[]`; `role-control-pm` carries `role_source` only inside `workstreams_detail` while `role-explicit-qa` puts it top level; no case checks scratch hygiene or leftover `.lock` files; and the skill-directory symlink still routes reads into the authoring repo, which the README warns graders to watch. The rubric-side items are the same blind spots r12 reported (R12-26): echo/presence checks, no memlog assertion, and no headless key-set check. The upgrade that would catch them is asserting the emitted block key-by-key against the captured `summary` and comparing rendered menu rows to `summary`.

## Findings

IDs match the findings JSON. `[reproduced]` means the reviewer ran the command or read the code path and observed the described behavior.

### 1. Separation of duties and handoff integrity

- **R13-01** `[reproduced]` `--as <role>` is an unattested identity switch. One session writes `ticket` as `dev`, then `review` and `done` as `qa`; `guard_self_approval` compares the builder with the claimed actor, so the script sees two roles where there is one session. No reason is needed when the claimed role owns the gate.
- **R13-02** `[reproduced]` `verify-return` accepts a `done` return with no `role` and no `action` when the two `--expect-*` flags are omitted. The ownership check never runs. Same as R13-21.
- **R13-03** `[reproduced]` A returned artifact is accepted on existence alone; the computed `changed` set is reported but never consulted, so any pre-existing file satisfies the contract.
- **R13-04** `[reproduced]` `validate` never requires a decided gate's `actor`. Delete one YAML line and the self-approval check is permanently disabled while validate stays green.
- **R13-19** `[reproduced]` `verify-return` has no `--workstream`; ownership is resolved from the active workstream, so a return for another workstream is checked against the wrong track, or none when paused.
- **R13-41** `[reproduced]` The self-approval guard is tested only through `ticket`. The `set` route for `tickets.<id>.gates.review` has no foreign-role test; the main suite also injects `--as <owner>`, so its `set` tests never exercise the guard.
- **R13-36** `[reproduced]` No test supplies exactly one `--expect-*-sha`; an `or` regression would accept a partially verified handoff.
- **R13-37** `[reproduced]` The `--allow-empty-artifacts` decision line is not asserted in the audit trail.

### 2. Ledger state machine and close

- **R13-25 / R13-35** `[reproduced]` `done --accept-missing-tickets` with no ticket closes the workstream, marks the empty build phase `done`, and leaves a ledger `validate` immediately rejects (`phases.build is done with no ticket built`). No test reaches that branch: every test using the waiver creates a ticket first.
- **R13-07** `[reproduced]` `done` rewrites every pending/active phase to `done` with no per-phase actor or reason, although a phase advance by a foreign role is supposed to need both.
- **R13-22** `[reproduced]` Phase evidence is append-only and cannot be cleared. An appended evidence file that is later deleted permanently traps close unless the user accepts a missing-evidence gap or hand-edits the ledger.
- **R13-23** `[reproduced]` A whole-phase `--replace` can carry evidence paths that do not exist; only `append` validates existence and containment.
- **R13-24** `[reproduced]` Appending evidence with a JSON number (`7`) stores an int and skips the path checks.
- **R13-26** `[reproduced]` Reopening an earlier phase and adding a ticket while later phases stay `done` produces a ledger validate rejects.
- **R13-28** `[reproduced]` `migrate` skips done and paused workstreams yet returns ok, so a corrupt closed workstream stays corrupt.
- **R13-29** `[reproduced]` An unknown gate in the ledger is counted as blocking by `summary`, but `set` refuses its id and `migrate` does not drop it.
- **R13-30** `[reproduced]` Pausing the active workstream clears `active_workstream` without stamping `updated`, so `summary` can report a sibling workstream's track, size, phase, and role.
- **R13-31** `[reproduced]` `done` requires every artifact pointer to resolve, including optional gates that were never decided; a stale optional pointer blocks close while `summary` says close is ready.
- **R13-33** `[reproduced]` `resize` with no flags is a no-op except that it clears `role_override`, changing `current_role`.
- **R13-38** `[reproduced]` No test asserts that a manual phase skip writes the reason into `phases.<phase>.note`; only init's auto-skip is covered, so the assignment can regress silently.
- **R13-34** `[reproduced]` A malformed `_bmad/config.toml` is refused by `init` but ignored by `done` and `reconcile`, which proceed on default folders.
- **R13-06 / R13-27** `[reproduced]` `init` appends a workstream after a model change by migrating the whole document first; a paused or done sibling workstream fails the append.
- **R13-05** `[reproduced]` The documented `init` snippet always passes `--model`; on an existing ledger with a silent detector it refuses as a downgrade.
- **R13-17** `[reproduced]` `init --force` always writes `plan.yaml.bak`; a second attempt overwrites the only backup.
- **R13-18** `[reproduced]` The ledger is saved before the audit line. A SIGKILL or harness timeout between the two leaves a decided gate with no audit record, and nothing cross-checks.
- **R13-08** `[reproduced]` `reconcile --write` can block an open gate, and once the artifact appears no documented command clears the block; `set ... passed` is refused.
- **R13-16** `[reproduced]` Without `ruamel.yaml`, the helper reports "cannot parse ledger" instead of a missing-dependency hint, and the hand-edit fallback then forbids presenting a gate no tool can validate.
- **R13-32** `[reproduced]` `init --force` on an absent path skips the reason check because the guard sits inside the `exists()` branch.
