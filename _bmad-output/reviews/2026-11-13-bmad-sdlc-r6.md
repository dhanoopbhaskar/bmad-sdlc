## Adversarial (16)

**1. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3033-3041, 515-533, 238-264`**

- **Problem:** A `set --path bmad --replace` payload can record `memlog` equal to the ledger path: the bmad branch only checks that the key is present, and `resolve_memlog`'s recorded branch never compares it to the ledger.
- **Fix:** Resolve the incoming memlog the way `resolve_memlog` does and fail when it equals the ledger; add the same comparison to `resolve_memlog`'s recorded branch; make `file_lock` refuse a path already locked in-process.
- **Consequence:** Verified: the command hangs forever on the ledger's own `.lock` after saving, and every later write command hangs too, so the ledger is bricked until a human edits YAML. `validate` and `summary` still report ok.

**2. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2994-3005, 3256-3299, 3303-3308`**

- **Problem:** The only lifecycle check on writes is `status == 'done'`; `set`, `append`, and `ticket` all accept phase, gate, ticket, and evidence writes on a paused workstream (with an explicit `--workstream`).
- **Fix:** Reject writes when the workstream status is `paused` unless the path is `status` or `active_workstream`, using cmd_done's wording: "workstream is paused; resume it before ...".
- **Consequence:** Verified: a paused workstream accepts `gates.plan.ux.status=skipped --reason demo`, yet `summary` keeps returning `next_action: null`, so decisions land where the conductor is told nothing can advance.

**3. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3191-3198, 1640-1648, 536-574`**

- **Problem:** `set --path bmad.model` and `init --model` on an existing ledger both call `apply_levels`, which flips a `done`/`skipped` phase back to `pending` when the new model makes a gate required; unlike `resize`, neither path needs or logs a reason.
- **Fix:** Collect the `phases.<p>.status->pending` entries from `apply_levels` in the model-change branches, fail without `--reason`, and log each reopened phase; share the helper with `cmd_resize`.
- **Consequence:** A signed-off phase silently regresses to pending while the audit trail records only "BMAD model set to ...", so a later reader cannot tell which phase changed or why (gate-matrix §Reopening requires the reason).

**4. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2567-2570, 3191-3195, compare 1574-1583`**

- **Problem:** `set --path bmad.model unknown` — the route SKILL.md:56 recommends for an existing ledger — performs the downgrade that `init --model unknown` refuses, with no reason and no `--force`.
- **Fix:** In the bmad.model branch, refuse `unknown` while the stored model is v6/current unless `--force --reason` is supplied, reusing init's message.
- **Consequence:** One `set` drops `plan.sprint` from required to optional on an epic v6 ledger and removes a required gate from the matrix with no recorded reason.

**5. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2951-2991, compare 2693-2700`**

- **Problem:** `set --path tickets.<id> --delete` returns before `_guard_ticket_node` runs, so a ticket whose `ticket`/`review`/`done` gates are `passed` is deleted with only `--reason`, while replacing it is refused for dropping decided gates.
- **Fix:** Before deleting, refuse a ticket with a `passed`/`overridden`/`skipped` gate and point at the reopen path, or record the deleted gate states verbatim in the audit trail.
- **Consequence:** Verified: a passed build/review/done trail is erased by one command and `validate` then reports a clean ledger.

**6. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3730-3751`**

- **Problem:** `migrate` recreates a missing gate as `open` and never re-checks the enclosing phase, so a phase already marked `done` stays `done` while the gate it just gained is undecided.
- **Fix:** After creating gate nodes, reopen the affected phase or fail with the exact repair, and never save a ledger the same command cannot make valid.
- **Consequence:** A ledger that `validate` rejects before migrate is rejected identically after it, while migrate reports ok and logs a `correction`, so the documented repair path repeats forever.

**7. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3543-3573`**

- **Problem:** Phase evidence is a flat path list with no gate id, and one entry short-circuits the per-gate artifact lookup for every required/conditional gate in that phase; `done` accepts a directory because it only tests `exists()` and `st_size`.
- **Fix:** Record phase evidence as `{gate, path}`, require `is_file()` and a matching gate id, and remove the `or phase_evidence` short-circuit so each gate still needs its own artifact key.
- **Consequence:** Verified from code: `append --path phases.plan.evidence --value .` plus the same for verify lets a workstream close with no SPEC, PRD, stories, ticket artifact, or trace — the "advance on file presence alone" failure gate-matrix:7 forbids.

**8. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3555-3569, 4016-4026`**

- **Problem:** `done` decides `plan.ux` by globbing `planning_artifacts` for DESIGN.md and EXPERIENCE.md and continues before consulting `artifacts.ux`, so the ledger's own UX pointer is ignored; `reconcile` mirrors the rule.
- **Fix:** Resolve both UX documents from the recorded pointer (add `ux_experience` or accept a directory pointer) and fall back to the planning-artifacts glob only when no pointer exists.
- **Consequence:** A ledger pointing `artifacts.ux` at a real DESIGN.md + EXPERIENCE.md pair elsewhere cannot close until the files are duplicated into the planning-artifacts tree.

**9. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:4125-4133, 4210-4222`**

- **Problem:** An omitted `evidence` key yields `raw_evidence is None`, `evidence: []`, and the evidence requirement is skipped; only an explicitly empty list is rejected.
- **Fix:** Require the key for a done return (`if 'evidence' not in returned: reasons.append('no evidence returned')`) rather than only checking a present-and-empty list.
- **Consequence:** Verified: `{"status":"done","artifacts":["out.md"]}` returned `ok: true` with no evidence, so handoff-protocol §Return contract's "evidenced, not merely asserted" rule is satisfiable by omission.

**10. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:4134, 4200-4208`**

- **Problem:** `--allow-empty-artifacts` waives the artifact requirement for any action; nothing resolves the action id or enforces the "action that produces no file" exception the docs describe.
- **Fix:** Resolve the current action from the ledger and enforce an allowlist inside `cmd_verify_return`, failing when the flag is used for any other action.
- **Consequence:** A done return with `artifacts: []` is accepted for every capability in the lifecycle, turning the return check into a status echo.

**11. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:888-899, 4412-4425, SKILL.md:29`**

- **Problem:** `summary` has no `--project-root` and `resolve_skill` returns the model alias whether or not that skill directory exists, so the command that produces `next_action.skill` cannot know what `detect` found installed.
- **Fix:** Give `summary` a project root (or persist `detected_skills` at init), call `read_skills`, and emit `next_action.skill_installed: false` with a blocked reason when the resolved skill is absent.
- **Consequence:** The headless rule "missing next_action.skill -> blocked" is unenforceable by the script; only a prompt-level cross-check against `detect.missing_core` prevents a handoff to an absent skill.

**12. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2467-2469, 2591-2609, 1766-1769`**

- **Problem:** `_validate_path` allows the single-segment workstream fields `name` and `started`, but `_validate_value` has no branch for either and `validate` type-checks neither.
- **Fix:** Require a non-empty string for `name` and an ISO-8601 shape for `started` in `_validate_value`, and assert both in `validate`.
- **Consequence:** Verified: `set --path name --value '[1,2]'` returned ok and `validate` returned no errors, so menus and `workstreams_detail` receive a list where a display name belongs.

**13. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2588-2590, compare 3500-3521`**

- **Problem:** An artifact pointer accepts any string at write time, including an absolute path outside `{project-root}`; the containment check exists only later in `done` and `reconcile`.
- **Fix:** In the artifacts branch of `_validate_value`, resolve against the command's project root and fail when the path leaves it, reusing done's message.
- **Consequence:** Verified: `set --path artifacts.spec --value /etc/hosts` returned ok, so a gate can be decided against a pointer the project cannot ship and the failure appears only at close.

**14. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:344-348`**

- **Problem:** `_load_toml` swallows `TOMLDecodeError` and returns `{}`, so a malformed `_bmad/config.toml` is indistinguishable from an absent one and `resolve_paths` silently falls back to default folders.
- **Fix:** Return `(data, error)` and surface `config_error` in `detect` and `init` instead of treating a parse failure as no configuration.
- **Consequence:** A broken config silently records default artifact folders, and every later evidence check scans the wrong directory while the real artifacts sit elsewhere.

**15. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3978-3990, 4030-4055`**

- **Problem:** `reconcile --write` applies orphan pointers only; `gates_to_block` and `phases_to_block` are computed and reported but never written, and no other command sets a gate to `blocked`.
- **Fix:** Under `--write`, set every gate in `gates_to_block` (and phase in `phases_to_block`) to `blocked` in the same save, log one correction per change, and report the applied list.
- **Consequence:** `blocked_gates` stays empty and the dashboard never marks a gate blocked, contradicting "a gate whose evidence pointer is missing is blocked, not open"; the conductor must hand-apply a list reconcile already computed.

**16. `SKILL.md:31, behavior at scripts/sdlc_plan.py:2093-2117`**

- **Problem:** The headless contract says `track` and `size` come from `summary.workstream`, but after `done` clears `active_workstream` the script returns `"workstream": null` and keeps the last track/size only at the top level.
- **Fix:** Emit a workstream object with `status: done` in summary's no-active branch, or change SKILL.md to read `summary.track`/`summary.size` with `summary.workstream` as the override when present.
- **Consequence:** A literal reading of the contract emits `track: null, size: null` for exactly the closed state the script preserves at the top level.

## Edge-Case Hunter (14)

**1. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3116-3128, 2610-2624`**

- **Problem:** `set --path gates.<phase>.<gate> --replace` writes a gate node without a `level`; `_validate_value` rejects `level` in the payload and the write path does not carry the previous value forward.
- **Fix:** For a phase gate node replacement, copy the existing `level` into the new node before saving, as the phase-node branch already does for `gate`.
- **Consequence:** `validate` warns "level missing; run migrate" after a documented node write, and the gate's required/conditional status is lost until migrate runs.

**2. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3303-3335, 3420-3435`**

- **Problem:** `ticket` adds or changes gates below a `done`/`skipped` build phase; it checks only the workstream status.
- **Fix:** Refuse ticket gate writes while `phases.build.status` is `done` or `skipped` until the phase is reopened.
- **Consequence:** The script writes a ledger its own `validate` call rejects for a done build phase with undecided gates.

**3. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2951-2973, 3455-3462`**

- **Problem:** `--delete` removes the only ticket of a `done` build phase; only the workstream status is checked.
- **Fix:** Refuse deleting the last ticket while `phases.build.status` is `done` or `skipped`, and name the phase reopen command.
- **Consequence:** `validate` then reports a done build with no ticket built, and `done` refuses to close the workstream.

**4. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2678-2682, 3036-3050`**

- **Problem:** `set --path tickets.<new-id> --replace` creates a ticket node without running the ticket order guards, so `done` can be `passed` while `review` is open.
- **Fix:** Refuse creating a ticket through `set`; require the `ticket` command for a new id, or run the same order guards on the whole node.
- **Consequence:** The create path bypasses the guard the replace path enforces, and `validate` then fails on the ledger it just accepted.

**5. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3256-3283, 3045-3052`**

- **Problem:** `append` has no done-workstream guard, so phase evidence or a decision can be appended to a closed workstream.
- **Fix:** Refuse `append` when the workstream status is `done` unless the command is the close event itself.
- **Consequence:** A closed workstream continues to accept evidence writes, changing the record after `done` declared it closed.

**6. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3262-3268, 2236-2250`**

- **Problem:** `append --path artifacts.<key>` on a missing key creates a list, turning an artifact pointer into a list.
- **Fix:** Refuse `append` for any path under `artifacts`; artifact pointers take `set`.
- **Consequence:** `validate` accepts a ledger whose artifact pointer is a list, and `done` stringifies the list into a bogus path.

**7. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3500-3523`**

- **Problem:** `done` checks an artifact with `exists()` and `st_size`, so a non-empty directory passes as evidence; `verify-return` correctly uses `is_file()`.
- **Fix:** Use `is_file()` for artifact and phase-evidence checks in `done` and `reconcile`.
- **Consequence:** A directory standing in for a required artifact lets the workstream close with no actual document.

**8. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3650-3661`**

- **Problem:** The close note lists only gates with status `overridden`; a required or conditional gate recorded as `skipped` with a reason is also an override but is omitted.
- **Fix:** Include `skipped` required/conditional gates in the close-note override list (or label them separately).
- **Consequence:** gate-matrix §Override rules says a required-gate override must be visible in the close summary, but a reasoned skip disappears from it.

**9. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:4286-4300`**

- **Problem:** `resize` from audit to another track treats only `passed`/`overridden` audit gates as decided, so a reasoned `skipped` review is erased when the synthetic ticket is removed.
- **Fix:** Count `skipped` as decided in that check, matching `_guard_reopen`.
- **Consequence:** A recorded skip decision disappears from the ledger on a track change.

**10. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3116-3128, 2731-2737`**

- **Problem:** A whole-node gate replacement that keeps a decided status but omits `override_reason` clears the reason; `_guard_decided_metadata` only guards explicit `override_reason`/`decided_at` paths.
- **Fix:** Carry the previous `override_reason` and `decided_at` into a node replacement unless the gate is reopened.
- **Consequence:** A documented node write erases the override history the close summary and status view depend on.

**11. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:3908-3920, 289-310`**

- **Problem:** Activation runs `reconcile` without `--write` (SKILL.md:73-78), but `plan_locked` always creates `<ledger>.lock`, so a read-only checkout still attempts a write.
- **Fix:** Skip the lock (or use a shared lock) for reconcile when `--write` is not set, or document the lock as a required side effect.
- **Consequence:** Activation fails on a read-only checkout or leaves a `.lock` file the scope guardrail did not expect.

**12. `.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:4454-4455`**

- **Problem:** `--gate` and `--status` use argparse `choices`, so an invalid value exits 2 with usage text instead of the JSON `{ok:false,error}` contract every other failure follows.
- **Fix:** Replace `choices=` with a type handler that calls `fail()`, or catch the argparse error and emit JSON.
- **Consequence:** A conductor parsing stdout as JSON breaks on a typo instead of reading a structured error.

**13. `.agents/skills/bmad-sdlc/references/ledger-schema.md:290`**

- **Problem:** The resume instruction says to set a passed gate from `gates_to_block` to `blocked` without `--reason`; `_guard_reopen` requires a reason for any decided gate moving to `blocked`.
- **Fix:** Add `--reason <why>` to the documented command and to the phase equivalent.
- **Consequence:** Following the documented recovery step is rejected by the script, so a fresh session cannot repair the ledger as instructed.

**14. `.agents/skills/bmad-sdlc/references/menu.md:97`**

- **Problem:** The status view tells the conductor to "resolve the blocker or override with a reason" for `<phase>.unblock`, but a blocked phase is not a gate and no command leaves that state.
- **Fix:** Name the clearing command: `set --workstream <id> --path phases.<phase>.status --value active`.
- **Consequence:** There is no documented way to leave the blocked-phase state, so the action recurs on every activation.
