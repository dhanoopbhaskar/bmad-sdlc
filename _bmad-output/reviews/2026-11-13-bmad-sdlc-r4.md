## Adversarial (18)

- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2339-2416,2419-2509,2795-2801`** — `set --path bmad --value '{"model":"current"}'` replaces the whole `bmad` block with no `--replace` and no `--reason`, and accepts a model the scalar `bmad.model` path rejects. **Fix:** add `bmad` to `replace_required` and validate the block, keeping `memlog`/`hub`/paths as strings. **Consequence:** with `init --memlog audit.md`, the write drops the recorded path and later writes land in `.memlog.md`; the audit trail splits and `validate` stays clean.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2893-2908`** — The documented switch `set --path active_workstream --value <id>` sets the target status to `active` unconditionally, so a `done` workstream reopens with no reason. **Fix:** refuse activating a done workstream or route it through the guarded status write. **Consequence:** reproduced — closed history becomes active, `validate` clean, audit only says `root active_workstream updated`.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2835-2842`** — The done-workstream guard fires only for target `active`; `status paused` downgrades a done workstream with no reason, after which `active` needs none either. **Fix:** require `--reason` for any transition out of `done`. **Consequence:** `done` → `paused` → `active` returns ok twice, `validate` clean, no reason recorded.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2828-2834,2909-2913`** — No workstream analogue of `_guard_active_phase`: `set --workstream ws-001 --path status --value active` leaves an already-active ws-002 active. **Fix:** add `_guard_active_workstream` that refuses a second active workstream or pauses the previous one. **Consequence:** the command returns `ok: true`, then `validate` errors `only one workstream may be active at a time`.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2696-2713`** — `_guard_phase_status` never checks the workstream status, so a phase can reopen on a `done` workstream without reopening the workstream. **Fix:** fail phase reopens when `workstream.status == "done"`. **Consequence:** on a genuinely closed ledger, `phases.build` becomes `active` while the workstream stays `done`; `validate` reports no error.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2828-2834 vs 3013-3017`** — `cmd_ticket` refuses every write on a done workstream, while `cmd_set` guards only a reopen; passing a still-open optional gate after close is accepted. **Fix:** apply the same refusal or document and log the allowed post-close writes. **Consequence:** reproduced — `set ... gates.close.retro.status passed` on a closed workstream returns ok and `validate` is clean; the two commands enforce opposite policies.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2818-2827,2589-2590,3060-3064`** — A decided gate cannot move to `passed` with `--reason` (the flag is rejected for a passed gate), and without a reason the write is rejected as a reopen; the documented transition is unreachable. **Fix:** allow `--reason` when the current status is decided and the target is `passed`. **Consequence:** skipped/overridden → passed always fails, contradicting `gate-matrix.md` §Reopening.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2596-2620`** — The phase `done`/`skipped` check exists only for `kind == "phase"`, so a ticket gate can reopen to `open` while `phases.build` is done. **Fix:** check the build phase in the ticket branch too. **Consequence:** the write returns ok, then `summary` reports `complete: false` on a done phase and `validate` errors.
- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2623-2648`** — `_guard_decided_metadata` finds the gate with `_node_at`, which splits on every dot; a dotted ticket id resolves to the wrong node and the guard no-ops. **Fix:** resolve with the ticket-aware logic used by `get_parent`/`_ticket_gate_index`. **Consequence:** reproduced — `set --path tickets.1.3.gates.review.override_reason --null` (and `decided_at`) returns ok on an overridden gate; `validate` then errors.

- **`.agents/skills/bmad-sdlc/scripts/sdlc_plan.py:2512-2531,2832-2834`** — `_written_gate` returns None for a whole `tickets.<id>` node, so the documented node-replacement form skips `_guard_reopen`, `_guard_ticket_order`, and `_guard_blocked_gate` for every gate inside. **Fix:** expand the node into per-gate checks or reject gate-bearing ticket-node replacement. **Consequence:** reproduced — `review: open` + `done: passed` via replacement returns ok while `ticket` refuses; a blocked review can be recorded passed.

## Overlapping findings

- **Whole-node replacement is the common seam.** `_validate_value` and `_written_gate` model only leaf gate nodes, so every parent-map replacement is a guard hole: `workstreams` (A1), `bmad` (A2), `tickets.<id>` (A12, edge 1), and `phases.<phase>` (A15). One fix — validate node writes by expanding them to the fields they contain — closes all five.
- **Dotted-id splitting is inconsistent.** `get_parent` and `_ticket_gate_index` are ticket-aware; `_written_gate`/`_gate_status_target` use `parts.index("gates")`; `_node_at` splits naively. A10, A14, edge 1, and V1 are the same disagreement seen through four commands.
- **The done-workstream rule was added at one entry point.** `active_workstream` (A3), `done → paused` (A4), phase reopen (A6), `set` after close (A7), and `--delete` (A18) all bypass it. Decide whether `done` is terminal, then enforce that at the workstream root.
- **Phase and ticket parity.** A9, A11, and A5 are the same missing mirror: `cmd_done` knows rules that `_guard_phase_status` and `_guard_active_phase` do not, and the workstream status has no active-sibling guard.
- **The reopen contract is split.** A8 (decided → passed unreachable) and V4 (reason discarded from the memlog) are two halves of the same rule: a reopen must be possible and its reason must be recorded.
- **The audit trail has both a code and a doc defect.** E3 (no expansion) and P9 (the docs promise it) are one issue; fix the code and the sentence together.
- **The eval suite grades the message, not the state.** V8 and V9 are independent of the write-loop defects above, but they explain why a fresh 62/62 did not catch any of them.
